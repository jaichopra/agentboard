# Security Model

## Defense in Depth

Agentboard has five security boundaries, each independent:

### 1. Schema Validation (Frontend)
Claude's output is constrained to a Zod schema. The frontend renders only pre-built Tremor components from a static registry. No `eval()`, no `dangerouslySetInnerHTML`, no dynamic component loading.

```
Malicious input → Claude → Zod validation → ❌ rejected
                                           → ✅ renders only known components
```

**Widget types are an enum.** Claude cannot invent a widget type that calls an arbitrary endpoint.

### 2. AST-Based Code Validation (Backend)
Pipeline code generated by Claude is parsed via Python AST before execution. Blocked patterns:
- Dangerous imports: `subprocess`, `pickle`, `ctypes`, `importlib`
- Dangerous calls: `eval`, `exec`, `__import__`, `globals`, `locals`
- OS operations: `os.system`, `os.popen`, `os.exec*`, `os.fork`, `os.kill`
- File writes: `open()` in write/append mode

### 3. Subprocess Sandbox (Runtime)
Even after AST validation, pipeline code runs in a separate Python subprocess — not in the main Modal process. If the subprocess crashes, the parent process is unaffected.

### 4. In-Process Database (Network)
LanceDB runs inside the Modal container. There is:
- No database port exposed
- No connection string to leak
- No network attack surface for the data layer
- No man-in-the-middle vector between app and database

### 5. Read/Write Separation
- **QueryEngine** (the hot path, always warm): READ-ONLY LanceDB access
- **IngestionRunner** (on-demand): WRITE access
- Frontend API routes can only call QueryEngine — never IngestionRunner directly

### 6. Table Namespacing
Each dashboard's data is stored in tables named `data_{dashboard_id}_{widget_id}`. The naming function sanitizes IDs to alphanumeric + hyphens. Dashboards cannot read or write other dashboards' tables.

### 7. Secrets Management
- Modal injects secrets at runtime via `modal.Secret`
- API keys never appear in environment files or client bundles
- S3 credentials are IAM-scoped to the LanceDB bucket only

## What Happens When...

**A user injects a malicious prompt?**
Claude generates a JSON spec. Even if the spec contains unexpected values, Zod validation rejects anything that doesn't match the schema. The widget types are a fixed enum — no arbitrary code can execute.

**A pipeline tries to exfiltrate data?**
AST validation blocks `subprocess` and network-based exfiltration tools. The pipeline can make HTTP requests (it needs to call APIs), but cannot write to the filesystem or spawn processes.

**A dashboard tries to access another dashboard's data?**
Table names are derived from dashboard IDs via a sanitization function. The QueryEngine only serves data for the requested dashboard/widget combination.

**The frontend is compromised?**
The frontend only has read access via QueryEngine endpoints. It cannot trigger pipeline execution, modify dashboard specs, or write to LanceDB.

## Audit Trail
S3 access logs record every read/write to the LanceDB backing store. Combined with Modal's execution logs, this provides a complete audit trail of who accessed what data and when.
