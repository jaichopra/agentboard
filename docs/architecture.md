# Agentboard Architecture

## Overview

Agentboard is a generative dashboard platform where AI agents power every widget. Users describe what they want to see, and Claude generates the dashboard spec, data pipelines, and refresh logic.

## Core Design Principles

### 1. Schema-Driven UI Generation
Claude generates validated JSON specs, not executable code. The frontend renders pre-built Tremor components from a static registry. No `eval()`, no dynamic imports.

### 2. In-Process Database
LanceDB runs inside the Modal container — no network hop to query data. S3 provides durability. Memory-mapped Lance files keep hot data in RAM.

### 3. Read/Write Separation
- **QueryEngine** (keep_warm=1): READ-ONLY access to LanceDB. High traffic hot path.
- **IngestionRunner**: WRITE access. Runs on-demand when pipelines execute.
- Frontend can only reach QueryEngine endpoints.

### 4. AST-Based Code Validation
Pipeline code generated by Claude is validated via Python AST analysis before execution. Dangerous patterns (eval, subprocess, os.system) are rejected.

### 5. Polling Cron for Refresh
A single Modal cron runs every 5 minutes, checks which dashboards need refresh, and dispatches IngestionRunner. No per-dashboard crons needed.

## Data Flow

### Non-technical user (chat-based)
1. User types prompt in chat UI
2. Next.js `/api/chat` sends to Claude via Anthropic API
3. Claude generates DashboardSpec JSON
4. Zod validates on the server (rejects invalid specs)
5. Frontend renders live preview
6. On publish: spec saved to LanceDB via Modal, pipelines created

### Engineer (SDK-based)
1. Engineer defines Dashboard + Widgets + DataPipelines in Python
2. `client.deploy()` serializes spec + pipeline code
3. Modal receives, validates code via AST, runs pipeline in subprocess
4. Results written to LanceDB
5. Dashboard accessible via URL
6. Refresh runs on cron schedule

## Component Details

### Dashboard Spec (Central Contract)
The Zod/Pydantic schema is the single source of truth. Defined in:
- TypeScript: `apps/web/lib/schemas/dashboard.ts`
- Python: `packages/sdk/src/agentboard/types.py`

### Widget Registry
Static map of widget type → React component. Located at:
- `apps/web/components/dashboard/widgets/index.ts`

### Modal Classes
| Class | keep_warm | Access | Purpose |
|-------|-----------|--------|---------|
| QueryEngine | 1 | READ | Serve widget data |
| DashboardAgent | 0 | — | Generate specs from prompts |
| DataAgent | 0 | — | Generate pipeline code |
| IngestionRunner | 0 | WRITE | Execute pipelines |
| RefreshScheduler | cron | READ | Trigger due refreshes |

### Security Boundaries
- Frontend → Zod validation → only known widget types render
- Pipeline code → AST validation → subprocess sandbox
- LanceDB tables → namespaced per dashboard (no cross-dashboard access)
- Modal secrets → injected at runtime, never in client bundles
